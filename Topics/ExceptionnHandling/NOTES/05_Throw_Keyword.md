
# throw Keyword

## Overview

The `throw` keyword is used to explicitly throw an exception.

Unlike exceptions automatically generated by the JVM, `throw` allows the programmer to manually create and throw an exception whenever a specific condition occurs.

It is commonly used for:

- Input validation
- Business rule validation
- Custom exception handling
- Preventing invalid program execution

---

# Why do we need throw?

Sometimes the JVM cannot determine whether a situation is an error.

For example,

- Age cannot be negative.
- Bank balance cannot be negative.
- Password cannot be empty.
- Product quantity cannot be less than zero.

These are application-specific rules.

In such cases, the programmer uses `throw` to indicate that something is wrong.

---

# Syntax

```java
throw new ExceptionType("Message");
```

Example

```java
throw new ArithmeticException("Division by zero is not allowed.");
```

---

# How throw Works

```text
Program Executes
       │
       ▼
Condition Checked
       │
 ┌─────┴─────┐
 │           │
False       True
 │           │
 ▼           ▼
Continue   Create Exception Object
               │
               ▼
      Throw Exception
               │
               ▼
Search Matching catch Block
               │
       ┌───────┴────────┐
       │                │
      Found          Not Found
       │                │
       ▼                ▼
 Handle Exception   Program Terminates
```

# Example 1 — Throwing an Exception

```java
public class Main {

    public static void main(String[] args) {

        throw new ArithmeticException("Division by zero.");

    }

}
```

Output

```text
Exception in thread "main"
java.lang.ArithmeticException: Division by zero.
```

### Explanation

- The programmer explicitly creates an `ArithmeticException` object.
- The JVM immediately throws the exception.
- Since there is no matching catch block, the program terminates.

---

# Example 2 — throw with try-catch

```java
public class Main {

    public static void main(String[] args) {

        try {

            throw new ArithmeticException("Invalid Operation");

        }

        catch (ArithmeticException e) {

            System.out.println(e.getMessage());

        }

        System.out.println("Program Finished.");

    }

}
```

Output

```text
Invalid Operation
Program Finished.
```

### Explanation

- The exception is manually thrown.
- The JVM searches for a matching catch block.
- The exception is handled successfully.
- Program execution continues.

# Example 3 — Input Validation

```java
public class Main {

    public static void main(String[] args) {

        int age = -5;

        if (age < 0) {

            throw new IllegalArgumentException("Age cannot be negative.");

        }

        System.out.println("Valid Age");

    }

}
```

Output

```text
Exception in thread "main"
java.lang.IllegalArgumentException:
Age cannot be negative.
```

### Explanation

The JVM does not know that a negative age is invalid.

The programmer defines this rule and throws an exception manually.

---

# Example 4 — Bank Balance Validation

```java
public class Main {

    public static void main(String[] args) {

        double balance = -1000;

        if (balance < 0) {

            throw new IllegalArgumentException("Invalid Account Balance");

        }

        System.out.println(balance);

    }

}
```

Real-world applications often use `throw` for validating business rules like this.

---

# throw vs JVM-generated Exceptions

JVM-generated exception

```java
int result = 10 / 0;
```

The JVM automatically throws an `ArithmeticException`.

---

Programmer-generated exception

```java
throw new ArithmeticException();
```

The programmer explicitly throws the exception.

---

# What Can We Throw?

Only objects that extend `Throwable` can be thrown.

Valid

```java
throw new ArithmeticException();

throw new IOException();

throw new NullPointerException();
```

Invalid

```java
throw new String("Error");
```

Reason:

`String` does not extend `Throwable`.

---

# throw with Custom Exceptions

The `throw` keyword is commonly used with custom exceptions.

Example

```java
if (salary < 0) {

    throw new InvalidSalaryException("Salary cannot be negative.");

}
```

# Best Practices

- Throw the most appropriate exception type.
- Provide meaningful exception messages.
- Validate input before throwing exceptions.
- Avoid throwing generic `Exception` unnecessarily.
- Use custom exceptions for business-specific problems.

---

# Common Mistakes

❌ Throwing generic `Exception`.

```java
throw new Exception();
```

Prefer a more specific exception whenever possible.

---

❌ Throwing exceptions without a meaningful message.

```java
throw new IllegalArgumentException();
```

Better

```java
throw new IllegalArgumentException("Age cannot be negative.");
```

---

❌ Using exceptions for normal program flow.

Exceptions should represent exceptional situations, not regular logic.

# Interview Questions

### 1. What is the purpose of the `throw` keyword?

It is used to explicitly throw an exception.

---

### 2. Can we throw multiple exceptions using one `throw` statement?

No.

A single `throw` statement throws only one exception object.

---

### 3. Can we throw checked exceptions?

Yes.

However, checked exceptions must either be handled using `try-catch` or declared using the `throws` keyword.

---

### 4. Can we throw custom exceptions?

Yes.

Custom exceptions are typically thrown using the `throw` keyword.

---

### 5. What can be thrown using `throw`?

Only objects that extend the `Throwable` class.

---

# Key Takeaways

- `throw` is used to explicitly throw an exception.
- It is commonly used for input validation and business rules.
- The thrown object must extend `Throwable`.
- The JVM searches for a matching catch block after an exception is thrown.
- If no matching catch block exists, the program terminates.
